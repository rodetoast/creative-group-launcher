# 제한 사내 파일럿 운영 계획

상태: **1인 동행 파일럿 승인·일정 확정 대기**. 이 문서는 실제 직원 PC에 접속하거나 설치하지 않는다. 패키지 선정/해시/채널 조건은 [선정안](PILOT_RELEASE_DECISION.ko.md), 직원 조작은 [직원 안내](PILOT_EMPLOYEE_GUIDE.ko.md), 장애 지원은 [기존 장애 대응서](../BOOTSTRAP_SUPPORT_AND_LIMITED_PILOT.ko.md)를 단일 기준으로 사용한다.

## 범위와 확정 항목

첫 참여자는1명. 실제 사용을 확인한 뒤 **총2~3명까지** 확대할지 별도로 판단한다. 인원 확대·추가 배포·새 Release는 자동 진행하지 않는다. 직원의 정상 업무 사용 가능성을 보는 단계이며 회사 앱5개의 내부 기능을 다시 시험하지 않는다.

| 확정할 항목 | 현재 상태 |
|---|---|
| 첫 참여 직원/PC | 미정. 자원자·지원 가능한 환경. 중요한 진행 작업이나 유일한 원본 데이터를 시험에 노출시키지 않음 |
| 담당자/대체 담당자/연락 수단·지원 가능 시간 | 미정 |
| 사용할 자산 | 선정안의 BD13 무변경 재사용을 추천. 최종 배포 승인 미정 |
| 설치일 D0 | 미정 |
| 초기 관찰 종료·확대 판단일 R | 미정. 실제 사용·종료 후 재실행 관측을 확보한 뒤 정함 |
| PC별 설치 I / 데이터 D / 증거 보관 위치 | 미정. 담당자가 실제 존재·쓰기 가능·경로 길이/분리 여부를 확인 |
| 장애 시 기존 업무 지속 수단 | 미정. 기존에 승인된 독립 업무 수단과 사용 가능 여부를 직원과 확인 |
| 시험 Latest10 유지 방침 | 승인 필요. 다른 실험의 Latest 변경 병행 금지라는 선정 조건을 확인 |

기존 런처나 테스트 등록이 있는 PC에 겹쳐 설치하지 않는다. 첫 대상은 새로 분리할 수 있는 환경으로 한정한다. 기존 설치 이전·폴더 병합·공용 데이터 이전이 필요하면 첫 파일럿에서 제외하고 별도 결정한다. 설치 권한 문제를 해결하려고 관리자 권한·ACL·PATH·보안 정책을 바꾸지 않는다.

## 일정과 운영 체크리스트

일정은 상대 단계이며 실제 날짜/성명은 위 표에 승인 후 기록한다. 이미 완료한 항목은 기존 기록을 재사용한다.

### 배포 전 — 담당자

- [ ] 참여자·담당자·연락/지원 시간을 지정하고 추천 패키지/시험 채널 사용을 승인받았다.
- [ ] 선정안의 정확한 파일명·SHA256·채널을 대조했다. 같은 이름의 다른 Setup이나 ZIP을 대신 쓰지 않는다.
- [ ] 기존 런처/테스트 설치와 등록, 실제 AppData/회사 앱 데이터의 위치를 확인했다. 새 I/D와 겹치지 않는다.
- [ ] 짧고 일반 사용자 쓰기가 가능한 경로를 결정했다. 직원 프로필 아래 짧은 새 폴더 등을 검토하되 실제 경로는 PC 확인 후 기록한다. C:\Dev 생성이나 관리자 권한을 전제로 하지 않는다.
- [ ] 기존 업무 수단이 런처 없이도 사용 가능하고, 시험 자료는 원본의 유일한 사본이 아님을 확인했다.
- [ ] 자동 장애 복구가 검증되지 않았고 설치 목록에 안 보일 수 있음을 참여자에게 안내했다.

### D0 — 동행 설치 및 정상 사용 시작

- [ ] 승인된 Setup을 담당자가 직접 다운로드/해시 대조해 실행한다. 이 후보에는 /DATA와 설치 위치를 명시해 기본 업무 데이터 경로로 설치되지 않게 한다. 구체적 실행 형식은 기존 BD13 인계서를 참고하며 실제 I/D를 기록한다.
- [ ] 마법사의 설치 위치를 직원과 확인하고, 설치 완료 후 Bootstrap 해시/생성 바로가기 대상·데이터 경로를 대조한다. I/D가 예상과 다르면 실행을 이어가지 않는다.
- [ ] 실제 시작 메뉴/선택한 바로가기로 최초 GUI를 확인한다. 초기 버전과 설치 상태를 기록한다.
- [ ] 직원에게 필요한 앱만 확인·설치한다. 모든 앱 재설치나 내부 기능 전수 시험은 하지 않는다. 직원이 필요한 기존 기능을 평소 업무 범위에서 사용할 수 있는지 확인한다.
- [ ] 제공되는 실제 런처 업데이트가 있으면 현재/대상 버전을 확인하고 GUI 승인으로 적용한다. 새 GUI와 정상 종료/같은 바로가기 재실행, 기존 앱 상태/작업 파일 보존을 기록한다. 이미 통과한 개발 시험 전체를 반복하지 않는다.
- [ ] 회사 앱의 실제 새 승인 버전이 없다면 '현재 버전/업데이트 대상 없음'으로 기록한다. 앱 업데이트 성공으로 부르거나 가짜 버전을 만들지 않는다.
- [ ] 오류·미확인·지원 시간을 있는 그대로 기록한다. 설치/GUI 실행 성공과 회사 앱 간 정식 버전 업데이트 성공을 구분한다.

### D0 이후 — 지원 담당자와 직원

- [ ] 다음 업무 사용 시 정상 실행/직원 업무 가능 여부를 짧게 확인한다. 일상 사용에 없는 장애를 억지로 재현하지 않는다.
- [ ] 장애가 나면 기존 장애 대응서에 따라 해당 PC의 추가 조작을 멈추고 원본 자료를 보존한다. 임의 삭제·재설치·포인터 수정으로 진행하지 않는다.
- [ ] 알려지지 않은 새 버전/채널 변화는 적용을 보류하고 담당자에게 확인한다. 시험 채널을 정식 운영 채널과 혼용하지 않는다.
- [ ] 판단일 R에 아래 기록을 함께 보고 총2~3명 확대/1명 유지/중단을 결정한다. 모든 날짜가 지났다는 이유만으로 자동 확대하지 않는다.

## 간단한 운영 기록

한 줄씩 기록하며 민감한 작업 파일·인증정보는 붙이지 않는다.

| 일자/PC 식별 | 실제 사용·시작 시도/실패 | 설치·업데이트 시도/실패 | 업무 사용 가능 여부 | 지원 건수/분·업무 중단분 | 자료 상태/미확인 | 조치·다음 결정 |
|---|---|---|---|---|---|---|
| 실제 관찰 후 기입 | 미관찰은0이 아닌 미확인 | 런처/회사 앱을 구분 | 직원 확인 | 실제 기록 | 의도한 작업 변경과 손상 구분 | 담당자 기록 |

문제율은 관측한 실패/시도 분모를 함께 적는다. 설치 실패율과 실행 실패율을 섞지 않는다.1명의 성공률을 제품 전체 안정성 통계로 확대하지 않는다. 지원 부담은 총시간과 반복 문의/업무 중단을 보고 다음 참여자까지 담당자가 감당할 수 있는지 판단한다.

## 진행·보류·중단 기준

**시작 가능:** 승인 자산/지원 담당자/분리 경로/대체 업무 수단이 모두 확정되고 파일 해시가 일치한다. B14 원인 규명·ProcMon·319개 회귀 재실행은 시작 전제 조건이 아니다.

**해당 PC 지원·확대 보류:** 한 번의 시작 실패, 원인 불명 파일 접근 오류, 로그/설치 상태 확인 불가가 생기면 그 PC의 추가 실행·변경을 멈추고 지원한다. 확인되지 않은 조치를 반복해 통과를 만들지 않는다. 설치 목록 비노출만으로 기술 조사를 다시 시작하지 않고 이미 정리된 직접 제거/지원 동선을 사용한다.

**확대 중단:** 서명/해시 검증 실패, 예상하지 않은 기존 데이터 손상·소실, 반복되거나 해결되지 않은 실행 불가, 우회·권한 상승이 필요한 상황, 대체 업무 불가 또는 지원 부담 초과. 새 참여자 배포/적용을 멈추고 담당자에게 이관한다. 정상 동작 중인 다른 PC를 자동 제거/롤백하지 않는다.

**총2~3명 확대 가능:** 첫 직원이 필요한 프로그램을 실제 사용할 수 있고, 정상 종료 후 재실행을 확인했으며, 미해결 실행 불가·데이터 손상·서명/해시 문제가 없다. 남은 안내성 문제와 실제 지원 시간을 검토해 담당자 및 사용자 승인을 받아 확대한다. 지원 가능 시간/판단일은 임의 숫자로 확정하지 않는다.

정식 전체 배포에는 별도 결정이 필요하다. 자동 장애 복구 미검증, 설치 목록 비노출, 정식 회사 앱 버전 간 업데이트 검증 한계는 남는다. 표시 버전 차이 같은 후속 개선은 기록하되1인 파일럿의 기술 조사를 무한 반복하는 사유로 삼지 않는다.
