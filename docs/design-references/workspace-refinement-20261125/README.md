# 작업 공간 개선 — 실행 상태, 바로가기, 정렬 및 테마

- 종류: GPT 디자인/동작 제안. 실제 구현 증거가 아님.
- 대상: Southpaw Tools Launcher (번호 없음), 현재 운영 0.2.2 기준.
- 시각 참고: [workspace.html](workspace.html). 정적 HTML/CSS로 색상·레이어·간격·상태의 의도를 전달한다. HTML 구현으로 기술을 바꾸라는 의미가 아니다. 실제 Qt Quick/QML과 기존 테마 토큰 및 컴포넌트를 우선 활용한다.
- 예시 카드의 상태와 아이콘은 설명용이다. 실제 카탈로그의 제품 표시명, 아이콘, 버전, app_id 및 목록을 그대로 사용한다. GPT 개발 관리 번호를 제품 UI에 추가하지 않는다.

## 1. 필터와 정렬

기존 '내 작업 도구' 제목 아래에 한 줄의 작은 컨트롤을 둔다. 좌측 세그먼트 필터(전체 / 설치됨 / 업데이트 가능), 우측 정렬 드롭다운(설치된 도구 우선 / 이름순 / 최근 업데이트순). 여유 공간이 없는 창에서는 줄바꿈하되 카드 면적을 과도하게 줄이지 않는다. 필터는 선택 상태를 보라색 반투명 표면으로 표현하고 개수는 실제 상태에서 계산한다. 선택 후 실제 표시 목록만 바뀌며 프로그램의 설치나 카탈로그 원본 순서는 변경하지 않는다.

- 기본은 전체 / 설치된 도구 우선. 선택을 사용자 설정에 저장하여 재실행 시 복원한다. 기존 설정 파일과 호환한다.
- 설치 우선 정렬은 설치 상태를 우선하고 동률은 기존 카탈로그 순서 등 안정적 기준으로 해결한다. 이름순은 표시명을 기준으로 대소문자에 강건한 정렬을 사용한다.
- 최근 업데이트순은 신뢰할 수 있는 개별 프로그램의 게시 날짜/갱신 일시를 확인해 최신부터 정렬한다. 런처 조회 시각이나 카탈로그 전체 게시 날짜를 개별 프로그램 날짜로 대체하지 않는다. 버전 문자열을 날짜처럼 사용하지 않는다. 현재 카탈로그에 필요한 정보가 없으면 미지원/날짜 미상 상태를 명확히 처리하고, 필요한 경우 데이터 계약 확장을 별도로 제안한다. 이 작업만을 위해 운영 카탈로그·서명 형식을 바꾸지 않는다.
- 실행 상태 변경 때문에 카드가 계속 이동하거나 상세 선택을 잃지 않도록 한다. 선택은 app_id로 관리하며 필터에서 제외되면 상세를 닫거나 현재 목록과 일치하는 상태로 처리한다. 업데이트 없음/설치 도구 없음의 빈 화면에는 짧은 설명을 표시한다.

## 2. 실행 상태와 버튼 위계

설치 여부와 실행 중 여부는 별개 상태다. 설치 경로의 실제 프로세스 탐지 및 기존 프로세스 추적을 활용하여 런처에서 실행하지 않은 인스턴스도 감지한다. 단순 EXE 파일명만으로 다른 설치나 다른 프로세스를 실행 중으로 오인하지 않는다. PyInstaller 자식 프로세스와 종료, 최소화, 런처 재실행 등의 경계를 고려한다. 적절한 주기의 비동기 갱신으로 UI를 차단하지 않는다.

| 상태 | 기본 버튼 | 권장 다크 색상 |
| --- | --- | --- |
| 설치됨, 미실행 | 실행 + 재생 아이콘 | #7445BC / hover #8555CE |
| 실행 중 | 열린 창으로 이동 + 창 아이콘 | 실행과 같은 브랜드 보라색, 실행 중 칩은 녹색 |
| 미설치 | 설치 + 다운로드 아이콘 | #303545, 밝은 중립 텍스트 #D9DDEA |
| 업데이트 가능, 미실행 | 업데이트 + 순환 화살표 | #274B60, 밝은 청색 텍스트 #D3EFFF |
| 작업 진행 중 / 안전상 불가 | 실제 진행 상태 또는 비활성화 | 기존 비활성 상태 토큰 |

상세 정보는 공통 outlined 보조 버튼을 유지한다. 색만으로 상태를 구분하지 않고 아이콘과 텍스트도 사용한다. 설치 버튼은 클릭 가능한 중립 액션이지 비활성화처럼 보이지 않아야 한다. 실행 중인데 업데이트가 있다면 상태를 동시에 알리고, 기존 실행 창 전환은 제공하되 교체·제거는 현재 안전 규칙으로 보류한다. 프로그램 강제 종료 금지. 현재 설치 및 실행 가능한 릴리스의 실행 계약을 보존한다.

## 3. 중복 런처 실행과 도구 독립 실행

사용자 보고는 도구 실행 중 **런처를 다시 실행**했을 때 Windows Bootstrap 실패/LauncherError가 표시되는 현상이다. 별개로 런처 내부에서 이미 실행 중인 도구를 다시 클릭하는 상황도 처리한다. 먼저 실제 진단 JSON(개인 경로는 공개 자료에서 제거), Bootstrap 및 GUI의 단일 인스턴스/잠금/업데이트 준비 코드를 확인하여 원인을 특정한다. 단순히 실행 중인 도구 때문이라고 가정하거나 모든 LauncherError를 정상 상태로 숨기지 않는다.

- 기존 런처가 실행 중이면 새 런처 인스턴스를 열지 않고 기존 런처 창 활성화를 우선한다. 런처가 종료된 상태이고 도구만 실행 중이면 런처가 정상 시작하며 도구의 실행 중 상태를 표시한다.
- 앱이 이미 실행 중이면 기존 창을 복원/활성화 시도한다. Windows 제한 등으로 전환이 실패하면 '이미 실행 중입니다. 작업 표시줄에서 열린 창을 확인해 주세요.'로 안내한다. 전환 성공을 확인한 경우에만 '열린 창으로 이동했습니다.'를 표시한다.
- 정상 중복 실행은 치명적 오류 모달 대신 기존 테마의 작고 비차단적인 안내로 처리한다. 진짜 오류의 진단 기록과 적절한 복구/재시도는 보존한다. 기존 잠금, Bootstrap ready/confirmed, 서명, rollback, 데이터 보존 보호를 해제하지 않는다.
- 런처 종료 후 도구가 계속 실행되는지와 런처 없이 도구가 시작되는지를 실제 코드/Windows에서 확인한다. 독립 실행이 불가능한 앱이 있다면 원인 및 해당 앱 제약을 보고한다. 검증 후에만 공통 UI 안내를 사용한다.

## 4. 바로가기

설치 완료 시 1회만 간결한 비차단 완료 영역을 제공한다: '설치가 완료되었습니다.' / '실행' / '바탕화면 바로가기 만들기' / 닫기. 설치 승인이 곧 바로가기 생성 승인은 아니다. 생성하지 않아도 정상 설치·실행이 가능하며 나중에 언제든 생성할 수 있다.

설치된 도구의 상세 패널: 앱 사용(상태에 맞는 기본 실행/창 전환, 설치 위치 열기), 바로가기(바탕화면 바로가기 만들기, 작업 표시줄 고정 방법), 고급 관리(기존 복원/제거 등). 바로가기는 낮은 강조의 아이콘+텍스트, 고급 관리는 접힌 상태를 우선한다. 카드는 현재 밀도를 유지한다. 미설치 상태에서는 바로가기 동작을 제공하지 않는다.

- 실제 설치 루트, 현재 승인된 릴리스 선택 방법, Windows .lnk 및 AppUserModelID, 기존 아이콘/working directory와 서명·해시 계약을 확인한다. 버전별 EXE에만 직접 연결하여 다음 업데이트 후 깨지는 바로가기를 만들지 않는다. 기존 안정 진입점/승인된 실행 경로 계약이 있다면 재사용한다. 없다면 새 안정 진입점 또는 안전한 갱신 방식의 최소 설계를 검토한다. 런처 GUI가 상주해야 하는 바로가기로 만들지 않는다. 기존 독립 실행과 보안 보호를 모두 만족하는 경로가 없는 경우 이를 명시하고 우회로 보호를 낮추지 않는다.
- 사용자 바탕화면의 실제 Windows known folder 위치를 사용한다. 기존 사용자 파일과 다른 바로가기를 무단 덮어쓰거나 삭제하지 않는다. 생성, 이미 존재, 실패를 실제 결과에 맞춰 안내한다. 제거 시 이 제품이 관리하는 바로가기만 안전하게 처리할 수 있는지 확인한다.
- 작업 표시줄 고정은 Windows 버전의 일반 사용자 UI를 안내한다. 자동 고정, 강제 정책/레지스트리 우회는 하지 않는다. '도구를 실행한 뒤 작업 표시줄 아이콘을 오른쪽 클릭하고 작업 표시줄에 고정을 선택하세요.' 실제 앱이 올바른 아이콘/그룹으로 실행되는지 확인한다.
- 검증이 된 경우 안내 문구: '설치된 도구는 런처 없이도 사용할 수 있습니다.' / '설치 후에도 언제든 바로가기를 만들 수 있습니다.'

## 5. 시각 스타일 — 배경과 표면의 깊이감

기존 Pretendard, 다크/라이트 테마, 회사 심볼과 실제 앱 아이콘, 카드 구성과 여백을 기준으로 발전시킨다. 버튼을 번쩍이는 그라데이션으로 바꾸는 작업이 아니라 **창 배경, 헤더, 카드, 상세 패널의 표면 레이어를 정교하게 분리**하는 작업이다.

| 토큰/레이어 | 다크 시안 기준값 |
| --- | --- |
| 창 전체 base gradient | 155deg, #191B28 (0%) → #141620 (60%) → #11131C (100%) |
| 헤더 뒤 은은한 보라 광원 | 좌상단, RGB(112,65,177) 알파 0.13 → 투명, 화면 약 46% 이내 |
| 보조 광원 | 우상단 RGB(68,87,147) 알파 0.08 → 투명, 약 45% 이내 |
| 헤더 표면 | RGB(37,38,55) 알파 .72 → RGB(30,30,45) 알파 .43 |
| 카드·상세 표면 | 145deg, RGB(43,46,62) 알파 .80 → RGB(30,33,46) 알파 .86 |
| 공통 1px 경계 | RGB(185,180,225), 알파 .17 |
| 선택 카드 표면 | RGB(64,48,86) 알파 .75 → RGB(32,34,49) 알파 .90; 외곽 #9C7BD4 |
| 기본 텍스트 | #F1EFF8 |
| 보조 텍스트 | #A9ADBF |
| 필터 선택 | #3B3056 / #E8D9FF |
| 모서리 | 카드/패널 12–14 DIP, 버튼 8–10 DIP |
| 그림자 | 낮은 불투명도(약 .07–.12), 부드럽고 절제된 그림자 |

값은 참조용이며 기존 테마 토큰과 시각 비교 후 조정한다. 그라데이션은 창 전체에서 자연스럽게 이어지게 하고 카드마다 강한 광택을 반복하지 않는다. 배경 위에 표면색을 알파 합성하는 방식이지 텍스트·아이콘·버튼을 포함한 카드 전체 opacity를 낮추는 것이 아니다. 배경 무늬가 글자 가독성을 저해하지 않아야 한다. 반투명은 앱 내부의 레이어를 의미하며 Windows 바탕화면 투과, acrylic/blur 강제, 무거운 ShaderEffect/상시 애니메이션을 요구하지 않는다. 기본 QML Gradient와 반투명 표면을 우선하고 지원/성능상 제약이 있으면 정적 배경 레이어로 단순화한다.

라이트는 별도 밝은 토큰 사용: 배경 #F7F6FC → #E9EAF3, 텍스트 #242437, 보조 #56596A, 경계 #D1CFE0, 중립 설치 표면 #FFFFFF / #343746. 보라색 실행은 유지하며 청색 업데이트 토큰은 라이트 대비에 맞게 재설계한다. 다크 토큰을 단순 반전하지 않는다. 카드/상세는 기존 responsive 구조를 유지하고 100–200% 배율 및 좁은 창에서 필터, 버튼, 긴 표시명/현행 언어 문구가 잘리지 않는지 확인한다. hover, focus, disabled, selected, pressed 상태를 일관되게 유지하고 키보드 탐색을 방해하지 않는다.

## 6. 완료 기준 및 범위

- 실제 원인 확인 및 변경 관련 검증: 도구 외부 시작/런처 종료·재실행, 중복 런처 시작, 실행 중 창 전환/실패 안내, 실행 중 업데이트·제거 보호, 바로가기 생성 및 버전 교체 후 경로 유지, 필터/정렬·설정 복원.
- 기존 검증 결과는 조건이 동일하면 재사용한다. 테스트를 위한 테스트, 전체 앱 재빌드, 불필요한 직원 PC 변경 금지. 실행 증거와 미검증을 구분한다.
- 다크/라이트 전체 목록, 실행 중 상세 패널, 설치 완료 안내, 좁은 창 대표 화면을 실제 Windows에서 가능한 범위로 촬영하여 docs/ui-reviews/에 기록한다. 필요한 경우만 합본 생성/첨부를 요청한다.
- 개발 브랜치 코드 및 프로젝트 상태, 중앙 허브 관련 요약을 의미 있는 범위로 갱신하고 결과와 커밋 고정 자료 링크를 보고한다. 디자인 시안과 구현 증거를 혼동하지 않는다.
- 운영 ZIP/카탈로그/Toast 호환 채널/Setup/키는 변경하지 않는다. 이번에는 개발 및 사용성 검토 단계이며 패키징·정식 배포는 사용자 승인 이후 별도로 진행한다.
