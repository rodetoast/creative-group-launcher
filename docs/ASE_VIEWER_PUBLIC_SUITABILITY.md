## 사용자 경로의 정확한 위치와 용도

ZIP 안 `README.md` 53행과 `resources/examples/README.md` 5행에 `C:\Users\SOUTHPAW GAMES\Desktop\ase_viewer`가 있다. 과거 저장 JSON과 예제를 복구한 출처를 설명하는 문구다. 사용자 이름·개발 폴더 구조를 드러내지만 인증정보나 실행 명령은 아니다.

실제 예제 로더는 `app_resource_path()`로 애플리케이션 리소스 루트 또는 실행 파일 옆의 상대 경로를 찾는다. 기준 소스 1822행과 7533행 이후에서 확인했다. 승인 EXE 주 스크립트에도 9개 상대 경로가 있고, 위 과거 절대 경로는 UTF-8·UTF-16 검색에서 0건이었다. 전체 압축 모듈에 모든 종류의 경로가 없다는 뜻은 아니다.

따라서 이 문서 경로를 삭제한다고 실행 경로를 고쳐야 하는 것은 아니다. 동봉 README의 개발·테스트·복구 이력, `MANUAL_TEST_CHECKLIST.md`, 릴리스 문서의 개발 빌드 경로는 공개 사용자 안내에 불필요하다. 원본 이력은 로컬에 보존하고 새 후보의 사용자 문서만 정리할 수 있다.

### 실제 위험과 확인 한계

- **공개 판단이 필요한 항목:** 위 9개 자산. 동봉 문서가 회사 내부 제작 도구용이라고 명시한다. 공개 재배포를 허용하는 저작권자·라이선스 문구는 확인되지 않았다. 회사 자체 제작인지, 외주·제3자 자산인지와 공개 허용 범위를 권리 담당자가 확인해야 한다. 파일명의 `_Public`은 허가 근거가 아니다.
- **확인된 노출:** 게임 이미지와 편집 가능한 캐릭터 자산이 ZIP에 실제 포함돼 있다. 미공개 게임인지, 이미 공개된 그림인지, 외부 권리가 있는지는 현재 증거로 확정할 수 없다. 외부 공개 이력을 확인하려고 회사 자산을 외부 서비스에 업로드하지 않았다.
- **불필요한 정보:** 위 사용자 폴더 경로와 개발·복구 이력. 실행 의존성은 확인되지 않았다. 사용자 안내 문서로 교체할 수 있다.
- **개인정보 검사 범위:** PNG의 파서가 반환한 추가 메타데이터는 모두 없었다. Aseprite 사용자 데이터는 색상 플래그만 있었고 사용자 텍스트·속성 묶음·외부 참조 청크는 없었다. 이는 검사한 메타데이터에 대한 결과이며, 모든 프레임의 이미지 내용이나 모든 문자열에 개인정보가 없다는 보증은 아니다.
- 형식 검사는 [Aseprite 공식 파일 규격](https://github.com/aseprite/aseprite/blob/main/docs/ase-file-specs.md)에 따라 수행했다. 악성코드 검사나 법적 권리 증명으로 대체할 수 없다.

## 제외했을 때의 영향과 A/B/C 선택

기준 소스의 `_prepare_example()`는 누락·해시·태그·이미지 검사를 먼저 수행하고, 성공한 뒤에만 `_apply_prepared_example()`로 적용한다. `_load_example()`는 준비 실패 시 오류를 알리고 기존 프로젝트를 유지한다. EX1/EX2 호출은 사용자 입력 경로와 전용 검사 경로에 있으며 기본 실행에 강제 호출되는 구조는 확인되지 않았다.

동봉 `RELEASE_v0.5.8.3.md`에는 **같은 EXE 해시**로 외부 예제 0/9 상태에서 `--check`와 `--check-sidebar-ui`가 종료 코드 0이었다는 기존 기록도 있다. 이는 참고 근거이며 이번에 실행해 재검증한 결과가 아니다. 기본 실행·사용자 파일 작업에 예제가 필수라는 증거는 없지만, EX1/EX2 버튼을 누르면 누락 안내가 발생하는 기능 저하는 남는다.

| 안 | 적용 조건과 판단 |
|---|---|
| A. 현재 ZIP 유지 | 9개 자산의 공개 재배포 승인이 확인되고 문서 경로 노출을 수용한다면 가능성을 검토할 수 있다. 현재는 승인 근거 부족으로 권장하지 않는다. |
| B. 문서 정리·예제 제외 | **최소 변경 권장.** EXE 바이트를 유지하고 새 후보 ZIP에서 외부 `resources/examples/`를 제외한다. EX1/EX2 사용 불가를 사용자 문서와 릴리스 노트에 표시한다. 원본 ZIP은 보존한다. |
| C. 소스 최소 수정·재빌드 | EX1/EX2 버튼을 숨기거나 비활성화해야 하거나, 공개 가능한 대체 예제를 계속 제공해야 하는 경우에만 필요하다. 대체 자산은 코드의 고정 해시·태그·프로필 매핑과 맞춰야 하므로 파일 교체만으로 처리할 수 없다. |

### B안 후보에 필요한 최소 변경과 검증 계획

1. 별도 승인 후 새 작업 폴더에만 후보를 만들고, `ase_viewer.exe`는 원본과 같은 해시로 유지한다. 내부 예제 9개와 그 출처 README를 제외하고 최상위 문서를 사용자 안내로 정리한다. 원본 승인 ZIP과 기준 소스는 변경하지 않는다.
2. **카탈로그 필수 경로도 후보에 맞춘다.** 현재 `required_paths`에는 외부 예제 9개와 예제 README가 있다. ZIP에서만 제거하면 기존 Installer가 필수 파일 누락으로 거부한다. 새 후보의 `required_paths`에서 이 10개를 제거하고 EXE 경로·해시 검증은 유지한다. 사용자 설정 보존 목록은 유지한다.
3. 기존 `admin.publish(required_paths=...)`가 이 변경을 지원하므로 새 엔진은 필요 없다. 현재 관리자 GUI는 기존 목록을 상속하고 CLI는 해당 인자를 노출하지 않으므로, 기존 GUI에서 ZIP만 바꾸면 된다고 안내해서는 안 된다. 승인된 후보 메타데이터와 기존 함수 인자를 명시적으로 맞추는 절차가 필요하다.
4. 원본과 다른 ZIP 해시·크기 및 새 불변 release_id를 부여하고 별도 패키징 변경임을 기록한다. 기존 release_id로 바이트를 바꾸거나 새 후보를 자동으로 승인본으로 승격하지 않는다.
5. 안전 추출·필수 파일·서명 카탈로그 검사를 하고, 별도 승인 범위에서 격리된 실제 실행으로 기본 시작·사용자 소유 파일 열기·정상 종료를 검증한다. EX1/EX2 누락 안내 뒤 합성 프로젝트·설정이 보존되는지도 확인한다. 현재 작업에서는 이 실행을 하지 않았다.

## 나머지 프로그램과 게시 순서

TileNamer, Ase-PS Bridge Pro, Pivot_Fixer는 이전 정적 검사 통과와 기술적 준비 상태를 유지한다. 구조·내장 DLL·리소스·원본 ZIP·메타데이터의 전체 감사를 다시 수행하지 않았다. 새 배포 차단 문제는 이번 조사에서 발견되지 않았다. 이것이 공개 권한·운영 키·직원 배포 승인까지 완료됐다는 의미는 아니다. AsepriteTagMaster는 승인 ZIP 부재로 계속 미게시다.

| 방식 | 필요한 최소 조건 | 판단 |
|---|---|---|
| 네 프로그램 동시 게시 | ase_viewer A안 권리 승인 또는 B/C 후보 검증·승인 완료 | 예제 기능·공개 범위 결정을 기다릴 수 있을 때 선택 |

기존 저장소 `toast-source/creative-group-releases`와 게시 엔진을 사용한다. 운영 카탈로그에는 Dummy 앱을 넣지 않고 기존 다섯 앱 ID를 유지하며 선택한 앱만 게시 상태로 둔다. 전체 ZIP 동봉 방식에서 세 프로그램이면 3 ZIP+카탈로그+서명으로 5자산, 네 프로그램이면 6자산이다. 기존 Dummy r1/r2/r3 Release는 그대로 보존한다.

- 회사 프로그램 자체의 공개 승인과 ase_viewer 예제의 권리 확인 또는 B안 기능 축소 수용·후보 승인.

## 수행·보존

제품 코드·프로젝트·원본 승인 ZIP을 수정하지 않았다. 프로그램 EXE·GUI 실행, 후보 ZIP 생성, GitHub 쓰기, 키 생성·채택, 실제 AppData·보안·LAN 설정 변경을 하지 않았다. 새 자료는 이 보고서와 감사 전용 증거뿐이다. 보존 대조와 Git 최종 상태는 같은 증거 폴더의 `preservation-after.json`, `existing-projects-after.json`, `git-after.txt`에 기록한다. 이번 변경은 문서·분석 자료이므로 전체 테스트를 반복하지 않았으며 기존 전체 회귀 결과를 그대로 인용했다.

사후 대조 결과 기존 6,809개 파일의 변경·누락은 0개다. 외부 다섯 프로젝트 292개 파일·HEAD·태그·Git 상태와 원본 승인 ZIP 4개도 동일하다. 런처 Git은 master / HEAD `32afb846d0bc69b38203a259dad71180cd4a14b5` / remote 없음 / staging 없음을 유지한다. 기존 미커밋 상태의 추가·삭제는 없고 이번 보고서만 새 미추적 파일로 추가됐다.
