# 런처 작업 공간 개선

2026-11-25 · 개발 브랜치 `codex/workspace-refinement-20261125` · [지정한 시안 및 명세](design-references/workspace-refinement-20261125/README.md)

## 실행 동작

이전 관리형 Bootstrap은 주 Bootstrap 잠금을 잡기 전에 `initialize`에서 기존 GUI가 보유 중인 `running.lock`을 다시 요청했습니다. 별도 설치 경로를 사용한 시험에서 실제 Windows 파일 잠금 충돌을 재현했습니다. 사용자 원본 진단 JSON 및 과거 WinError 5 원인은 확인되지 않았습니다.

이제 정상 Bootstrap이 시작 잠금을 확보한 뒤 초기화와 복구를 수행합니다. 같은 설치의 시작 잠금이 이미 점유된 경우, 확인된 세션의 PID, 생성 시각, 전체 EXE 경로를 대조해 창 전환을 시도합니다. 아직 준비 중이거나 Windows에서 전환을 허용하지 않으면 짧은 안내를 표시합니다. 권한 오류, 손상, 교체 작업자의 실패는 기존 진단 경로를 사용합니다.

도구 실행은 런처 프로세스와 연결된 입출력이나 PyInstaller 내부 환경 없이 시작합니다. 주기적인 백그라운드 검사에서 앱 루트 내 전체 실행 파일 경로를 확인하므로 런처 외부에서 시작한 도구도 표시할 수 있습니다. 앱 설치·업데이트·제거 시 라이브 프로세스 여부는 기존 엔진에서 다시 확인합니다.

## 작업 공간과 바로가기

필터와 정렬을 기존 UI 설정 파일에 저장합니다. 최근 업데이트순은 검증된 카탈로그의 개별 `published_at` 값만 쓰며 날짜 미상은 끝에 표시합니다. 창·헤더·카드·상세 표면은 QML 그라데이션과 반투명 색으로 구성했습니다. 실행은 보라색, 설치는 중립색, 업데이트는 청색을 사용합니다.

설치 완료 또는 상세 패널에서 사용자가 원할 때만 바탕화면 링크를 만듭니다. 링크는 고정 Bootstrap과 앱 ID를 가리킵니다. 새 Bootstrap은 현재 선택된 설치 릴리스의 영수증, 서명 증거 및 실행 파일 해시를 확인합니다. 버전별 EXE를 직접 가리키지 않으므로 업데이트 뒤에도 경로가 같습니다. 구 Bootstrap 사용 중에는 해당 버튼을 활성화하지 않으며, 검증 증거가 없는 설치는 바로가기에서 실행을 거부합니다. 이름이 같은 다른 링크를 보존하며, 제거 후 기존 링크 자동 정리는 구현 범위에서 제외했습니다.

작업 표시줄 안내는 Windows에서 고정 가능한 경우 안정적인 링크를 사용하도록 설명합니다. Windows가 메뉴를 제공하는지, 실행 중 도구가 해당 링크와 같은 AppUserModelID로 그룹화되는지는 확인되지 않았습니다. 바로가기 전용 앱 아이콘 및 AppUserModelID 부여도 후속 검증 범위입니다.

## 확인 범위

- 관련 자동 시험에서 중복 초기화 잠금, 권한 오류 진단, 카탈로그 정렬·필터 저장, QML 및 설치 엔진 경로를 확인했습니다.
- 격리된 서명 fixture에서 같은 앱 ID로 이전·현재 두 릴리스에 연결되고 서명 증거를 제거하면 실행을 거부하는지 확인했습니다.
- 실제 Windows 프로세스의 전체 경로로 외부 실행을 감지했습니다. 임시 폴더에서 Windows COM 링크 생성, 같은 링크 재사용과 다른 대상 덮어쓰기 방지를 확인했습니다.
- 시험 세션에서 Win32가 전경 전환을 허용하지 않았습니다. 실제 도구 창 전환 성공과 5개 도구의 독립 동작은 미검증입니다.
- 실제 Windows Qt 창에서 합성 상태로 다크·라이트, 상세·안내 및 좁은 창을 확인했습니다. [검토 갤러리](ui-reviews/workspace-refinement-20261125/README.md)
- 이번 작업은 소스 및 UI 검토 단계입니다. 관리형 ZIP이나 운영 서명 후보를 만들지 않았고 Rod15·Toast9와 직원 설치 환경은 작업 대상에서 제외했습니다.
