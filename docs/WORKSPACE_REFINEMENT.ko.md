# 런처 작업 공간 개선

2026-11-25 · 개발 브랜치 `codex/workspace-refinement-20261125` · [지정한 시안 및 명세](design-references/workspace-refinement-20261125/README.md)

## 실행 동작

이전 관리형 Bootstrap은 주 Bootstrap 잠금을 잡기 전에 `initialize`에서 기존 GUI가 보유 중인 `running.lock`을 다시 요청했습니다. 별도 설치 경로를 사용한 시험에서 실제 Windows 파일 잠금 충돌을 재현했습니다. 사용자 원본 진단 JSON 및 과거 WinError 5 원인은 확인되지 않았습니다.

이제 정상 Bootstrap이 시작 잠금을 확보한 뒤 초기화와 복구를 수행합니다. 같은 설치의 시작 잠금이 이미 점유된 경우, 확인된 세션의 PID, 생성 시각, 전체 EXE 경로를 대조해 창 전환을 시도합니다. 아직 준비 중이거나 Windows에서 전환을 허용하지 않으면 짧은 안내를 표시합니다. 권한 오류, 손상, 교체 작업자의 실패는 기존 진단 경로를 사용합니다.

도구 실행은 런처 프로세스와 연결된 입출력이나 PyInstaller 내부 환경 없이 시작합니다. 주기적인 백그라운드 검사에서 앱 루트 내 전체 실행 파일 경로를 확인하므로 런처 외부에서 시작한 도구도 표시할 수 있습니다. 앱 설치·업데이트·제거 시 라이브 프로세스 여부는 기존 엔진에서 다시 확인합니다.

## 작업 공간과 바로가기

필터와 정렬을 기존 UI 설정 파일에 저장합니다. 최근 업데이트순은 검증된 카탈로그의 개별 `published_at` 값만 쓰며 날짜 미상은 끝에 표시합니다. 창·헤더·카드·상세 표면은 QML 그라데이션과 반투명 색으로 구성했습니다. 실행은 보라색, 설치는 중립색, 업데이트는 청색을 사용합니다.

설치 완료 또는 상세 패널에서 사용자가 원할 때만 바탕화면 링크를 만듭니다. 링크는 고정 Bootstrap과 앱 ID를 가리킵니다. 새 Bootstrap은 현재 선택된 설치 릴리스의 영수증, 서명 증거 및 실행 파일 해시를 확인합니다. 버전별 EXE를 직접 가리키지 않으므로 업데이트 뒤에도 경로가 같습니다. 구 Bootstrap 사용 중에는 해당 버튼을 활성화하지 않으며, 검증 증거가 없는 설치는 바로가기에서 실행을 거부합니다. 이름이 같은 다른 링크를 보존하며, 제거 후 기존 링크 자동 정리는 구현 범위에서 제외했습니다.

작업 표시줄 안내는 Windows에서 고정 가능한 경우 안정적인 링크를 사용하도록 설명합니다. Windows가 메뉴를 제공하는지, 실행 중 도구가 해당 링크와 같은 AppUserModelID로 그룹화되는지는 확인되지 않았습니다. 바로가기 전용 앱 아이콘 및 AppUserModelID 부여도 후속 검증 범위입니다.

## 확인 범위

- 관련 자동 시험에서 중복 초기화 잠금, 권한 오류 진단, 카탈로그 정렬·필터 저장, QML 및 설치 엔진 경로를 확인했습니다.
- 격리된 서명 fixture에서 같은 앱 ID로 이전·현재 두 릴리스에 연결되고 서명 증거를 제거하면 실행을 거부하는지 확인했습니다.
- 실제 Windows 프로세스의 전체 경로로 외부 실행을 감지했습니다. 임시 폴더에서 Windows COM 링크 생성, 같은 링크 재사용과 다른 대상 덮어쓰기 방지를 확인했습니다.
- 시험 세션에서 Win32가 전경 전환을 허용하지 않았습니다. 실제 도구 창 전환 성공과 5개 도구의 독립 동작은 미검증입니다.
- 실제 Windows Qt 창에서 합성 상태로 다크·라이트, 상세·안내 및 좁은 창을 확인했습니다. [검토 갤러리](ui-reviews/workspace-refinement-20261125/README.md)
- 이번 작업은 소스 및 UI 검토 단계입니다. 관리형 ZIP이나 운영 서명 후보를 만들지 않았고 Rod15·Toast9와 직원 설치 환경은 작업 대상에서 제외했습니다.

## 작업 공간 후속 마감 (2026-11-25)

[Windows 화면 갤러리](ui-reviews/workspace-followup-20261125/README.md) · [독립 Windows 시험 인계](WORKSPACE_WINDOWS_HANDOFF.ko.md)

- 정렬 드롭다운의 테마 화살표, 상세 패널의 아이콘 액션 행, 목록을 밀지 않는 설치 완료 안내, 실행 중·업데이트 가능 상태를 반영했습니다. 실행 중에는 기존 창 이동을 제공하며 설치 엔진의 실행 중 변경 보호를 유지합니다.
- 바로가기를 만들 때 앱 잠금 아래 설치된 현재 릴리스의 영수증·서명 증거·실행 파일 해시를 확인합니다. Windows EXE에서 아이콘을 가져와 사용자 데이터의 고정 경로 `shortcut-icons/<app_id>.ico`에 기록합니다. 바탕화면 링크의 대상은 안정 Bootstrap과 앱 ID입니다. 업데이트나 보관 릴리스 정리가 사용자 링크와 ICO를 깨뜨리지 않습니다. 아이콘이 없는 EXE는 바로가기를 만들고 해당 상태를 안내합니다. 이미 있는 링크는 바이트를 바꾸지 않습니다.
- 임시 폴더에서 Windows EXE 아이콘 추출, ICO 읽기, COM 링크의 대상·인수·작업 폴더·아이콘 경로, 이름 충돌 보존을 확인했습니다. 별도 WinForms 시험 앱이 실행을 요청한 Python 프로세스가 종료된 뒤에도 살아 있고 새 감지기에서 보이는 것을 확인했습니다. 기존 서명 설치 시험도 재사용했습니다. 5개 제품의 실제 독립 실행과 탐색기·작업 표시줄은 시험 PC에서 확인해야 합니다.

### 작업 표시줄과 전경 전환

링크가 설치할 때부터 가리키는 실행 파일은 Bootstrap이고 실제 도구 EXE는 별도 프로세스입니다. Windows에서 한 작업 표시줄 그룹으로 묶으려면 링크와 도구 창 또는 프로세스에 동일한 앱 고유 AppUserModelID가 있어야 합니다. 현재 도구 링크에 ID를 단독 부여하지 않았습니다. 각 도구가 정한 실제 ID를 먼저 조사하고, 새 ID를 도입한다면 해당 도구가 첫 창 생성 전에 같은 ID를 적용해야 합니다. 잠금·레지스트리·Explorer 고정 정책을 우회하거나 임의로 고정하지 않습니다. 바로가기의 메뉴에서 사용 가능한 표준 고정만 안내합니다. [Microsoft AppUserModelID](https://learn.microsoft.com/en-us/windows/win32/shell/appids)

전경 전환은 확인된 PID에서 현재 전경 또는 마지막 활성 팝업을 확인하고, 최소화 복원 후 표준 요청만 보냅니다. 이전 실패에서 Windows의 내부 거절 사유는 확인되지 않았습니다. 표시 가능한 최상위 창이 없는 경우와 전경 요청을 확인하지 못한 경우를 경로 없는 디버그 메시지로 구분합니다. 전경 잠금, 활성 메뉴, 다른 데스크톱 등은 가능한 조건이며 API가 내부 거절 사유를 확정해 주지는 않습니다. 실제 전경 소유권을 확인했을 때만 성공을 알립니다. 창이 없는 상태나 Windows에서 전경 전환을 허용하지 않는 경우에는 사용자에게 작업 표시줄에서 확인하도록 안내합니다. [Microsoft SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)

### 제거 시 관리형 링크 정리 검토

현재 링크에는 생성 당시 소유권 증거가 없습니다. 따라서 자동 삭제를 적용하지 않습니다. 후속 구현 시 신규 링크 생성이 성공한 직후에만 앱 ID, 정규화한 Desktop 경로, 설치별 안정 진입점, 고정 인수, 파일 식별값과 SHA-256을 관리 기록에 남기는 방식을 제안합니다. 제거 커밋 이후에만 현재 Desktop known folder 바로 아래에서 실파일·링크 속성·식별값·해시가 모두 일치할 때 해당 링크 하나를 정리합니다. 기존 링크 재사용, 사용자 변경, 파일 이동, 경로 재지정 또는 기록 누락은 보존 케이스입니다. 시험에서는 사용자 링크, 작업 표시줄 고정 복사본, ICO를 삭제하지 않습니다.
